A.1

Source photographs

All photographs in this report were supplied by the author for this assignment. Three overlapping sets depict a basketball court, an indoor lounge, and a city view; two additional photographs show book covers for rectification. The intended mosaic model is camera rotation about a fixed center. Camera motion was not measured, and depth-dependent residuals are consistent with foreground parallax and departures from that model.

All coordinates use (x, y) pixel centers, with the origin at the top-left. Original files are preserved. The working images are antialiased and reduced to at most 1,400 pixels on their longest side. Saved original-to-working matrices carry annotations into the resized image frame.

1. Basketball court

Three central frames of the basketball-court sweep (IMG_1242–1244) share the window wall and backboard. IMG_1243 is the reference.

The central three frames give a finite projective mosaic. The full six-image sweep crosses the projective horizon in this reference frame; IMG_1241, IMG_1245, and IMG_1246 are retained locally as supplemental inputs.

2. Lounge

Four overlapping lounge views, ordered IMG_1247, IMG_1248, IMG_1250, IMG_1249. IMG_1248 is the reference; the last two images are ordered by scene overlap rather than filename.

3. City panorama

Three overlapping outdoor views (IMG_1251–1253), with IMG_1252 as the reference. Buildings provide static landmarks distributed across the lower half of the images; the sky is not used for manual annotations.

What the projective model assumes

A single homography describes a plane, or an arbitrary scene viewed by a camera rotating about a fixed center of projection. Handheld translation, changing depth, moving objects, and lens distortion can leave residual misalignment even when the fitted points agree. The source sets are retained so these limits can be inspected directly.

A.2

Recovering homographies

A homography maps a source point to a destination point up to scale: [u, v, 1]ᵀ ∼ H [x, y, 1]ᵀ. Fixing h₃₃ = 1 leaves eight unknowns. Each correspondence contributes two equations, so four nondegenerate pairs are the minimum. The manual mosaics use more than four pairs and solve an overdetermined system.

One correspondence
[ x  y  1  0  0  0  −ux  −uy ] h = u
[ 0  0  0  x  y  1  −vx  −vy ] h = v

h = [h11 h12 h13 h21 h22 h23 h31 h32]ᵀ

Stacking n correspondences gives A ∈ ℝ2n×8 and b ∈ ℝ2n. computeH centers each point set and scales its mean distance from the origin to √2, solves with numpy.linalg.lstsq, and transforms the solution back into pixel coordinates. Rank-deficient point sets are rejected. Normalization improves conditioning without changing the geometric model.

Denormalize
H = Tdestination⁻¹ Hnormalized Tsource; then H ← H / h33

They are rounded for readability; full-precision values and the annotated points are included in the measurement download. A.3

Inverse warping and interpolation

Forward splatting can leave holes. Instead, each output pixel is mapped backward by H⁻¹ and sampled from the source. Automatic canvas bounds come from the transformed image corners. Rectification uses an explicit finite output rectangle. A separate validity mask distinguishes missing samples from valid black pixels.

Inverse mapping
[x′, y′, w′]ᵀ = H⁻¹ [u, v, 1]ᵀ;  (x, y) = (x′/w′, y′/w′)

Nearest neighbor

Round the source coordinates to the nearest integer pixel and copy that value. The method keeps discrete source values but can produce jagged edges and blocky fine detail.

Sample
Iout(u,v) = I(round(x), round(y))

Bilinear interpolation

Let x₀ = floor(x), y₀ = floor(y), a = x − x₀, and b = y − y₀. Blend the four neighboring source pixels using the weights below. This smooths edge transitions at additional arithmetic cost.

Sample
(1−a)(1−b) I(x₀,y₀) + a(1−b) I(x₀+1,y₀)
+ (1−a)b I(x₀,y₀+1) + ab I(x₀+1,y₀+1)

Both methods are implemented directly in NumPy. They use the same closed domain of valid source pixel centers; the last row or column repeats its boundary neighbor for bilinear sampling. Neither method calls a library interpolation or projective-warp routine.

Bilinear interpolation is slower in these measurements because each output sample combines four neighboring values. It produces more continuous letter contours in the close-ups, while nearest neighbor retains sharper intensity jumps and visible stair steps. Neither is a ground-truth reconstruction: a single photographed surface provides no reference image for PSNR or geometric accuracy.

The near-zero four-corner fit residual only confirms that the computed homography maps its own four constraints correctly. It does not measure corner annotation accuracy, surface planarity, or the unknown physical aspect ratio.

A.4

Blending into a shared frame

Pairwise homographies are composed into the selected reference frame. The reference image keeps the identity transform. All transformed source corners determine a common canvas, and every source is inverse-warped into it using bilinear interpolation.

Feathering
M(u,v) = Σᵢ wᵢ(u,v) Iᵢ(u,v) / Σᵢ wᵢ(u,v)

Each source receives a tent-shaped weight proportional to its distance from the nearest image boundary, normalized to one at its maximum. A positive one-pixel floor preserves isolated edge pixels. The image and its weights are warped together; invalid samples receive zero weight. The overlap is a normalized weighted average, so no image simply overwrites its neighbor.

Feathering reduces hard intensity seams, but it cannot repair a wrong transformation or remove two projections of a moving object. Transparent canvas regions indicate no source coverage. The full projective footprint is retained, making edge stretching and coverage visible.

Optional extension: preserve fine detail

A two-band experiment retains the same automatic homographies. It combines a mask-normalized Gaussian lowpass (σ = 16 working pixels) using feather weights, then takes the fine residual from the source with the largest feather weight. A Gaussian transition (σ = 1 pixel) softens the ownership boundary. This makes the lounge fixture clearer, but an ownership boundary can create a visible cut through another object. All original feather baselines are retained. The court additionally uses the source-preservation refinement described next.

B.1

Harris corners and spatial coverage

The supplied Harris implementation detects single-scale corner candidates in a grayscale image. Its 20-pixel border exclusion leaves room for descriptor windows. Harris responses alone can cluster many detections around a textured object; adaptive non-maximal suppression spreads the selected features across the available image structure.

ANMS radius
rᵢ = minⱼ ‖xᵢ − xⱼ‖₂, subject to fᵢ < 0.9 fⱼ

For each candidate i, the radius is its distance to the nearest sufficiently stronger corner. The largest radii are retained, up to 500 features per image. Candidates without a stronger suppressor receive a finite radius larger than the candidate cloud’s diagonal; ties are resolved by response and input index. The implementation evaluates all candidate pairs in bounded-memory chunks. Descriptor validation can subsequently remove low-contrast patches.

B.2

A descriptor from a larger neighborhood

A small patch is more useful when it summarizes a larger neighborhood. Each descriptor is an axis-aligned 8 × 8 grid sampled from a 40 × 40-pixel window, after Gaussian smoothing with σ = 2 pixels. Grid samples are five pixels apart, at the centers of the eight bins. The sampling uses the same explicit four-neighbor bilinear formula, without a library interpolation call.

Bias / gain normalization
d = (p − mean(p)) / std(p),   p ∈ ℝ⁶⁴

Mean subtraction removes an additive intensity offset; division by the standard deviation removes positive multiplicative gain. Nearly constant patches are discarded instead of dividing by a negligible standard deviation. This normalization does not make descriptors rotation-invariant or scale-invariant. The implementation follows the assignment’s single-scale, axis-aligned simplification of MOPS.

B.3

Matching distinctive features

For every source descriptor, compute squared Euclidean distance to all target descriptors and find the nearest and second-nearest neighbors. A match must be clearly better than its closest alternative. This rejects many repeated or otherwise ambiguous patches before geometric fitting.

Ratio test
ρ = ‖dsource − dnearest‖₂² / ‖dsource − dsecond‖₂² < 0.5

The configured threshold 0.5 applies to squared distances, equivalent to 0.707 on ordinary Euclidean distances. Equal-distance ties and ambiguous 0/0 matches are rejected. The photographic pipeline uses the forward ratio test; reciprocal nearest-neighbor filtering is available in code but is not enabled for these results.

The ratio test measures descriptor distinctiveness, not geometric correctness. Green and red lines in the following figures show the later RANSAC decision: green matches support the estimated projective model, and red matches were rejected by its reprojection threshold.

B.4

A robust homography from noisy matches

Descriptor matches include outliers. A custom RANSAC loop repeatedly samples four distinct correspondences, fits a homography with computeH, and scores every match using forward reprojection distance. Degenerate samples are skipped. Hypotheses are ranked first by inlier count and then by median inlier error.

Inlier test
eᵢ = ‖project(H [xᵢ, yᵢ, 1]ᵀ) − [uᵢ, vᵢ]ᵀ‖₂ ≤ 3 pixels

The trial budget adapts to the observed inlier fraction using four-point sampling and a target confidence of 0.995, with a maximum of 5,000 attempts. The best consensus is refitted using all its inliers, with repeated refinement while support remains stable or improves. The final mask is recomputed from the returned homography.

Adaptive trial estimate
N = ceil(log(1 − confidence) / log(1 − inlier_fraction⁴))

The run uses seed 671 plus the pair index. A scene pair must have at least 8 inliers and an inlier fraction of at least 20%. These are minimum support checks, not guarantees of a correct photograph-wide alignment.

Validation and limitations

The photographic results test whether the components work together on real data, while known-answer tests check implementation behavior. A synthetic diagnostic is kept separate from the three original-photo mosaics and is not counted as a photographic submission example.

49 automated tests passed. Checks cover homography recovery and degenerate inputs, explicit inverse sampling and valid black pixels, ANMS and descriptors, ratio matching, RANSAC with outliers, transform chains, and project configuration. An independent degeneracy audit re-fitted all seven automatic photograph pairs from their saved matches; the corrected validation produced identical matrices, inlier masks, and trial counts. Five additional tests verify mask handling, detail ownership, and constant-field preservation in the optional two-band compositor. Two further tests verify that protected reference pixels remain exact and that the transition preserves coverage.

Implementation boundary

The homography system, inverse mapping, nearest and bilinear sampling, feathering, ANMS, descriptor normalization, ratio matching, and RANSAC are implemented explicitly. NumPy provides linear algebra; SciPy provides Gaussian smoothing; the supplied Harris implementation is used as permitted. Pillow handles image I/O and orientation, and matplotlib produces diagnostic figures.

Limitations that affect interpretation

  • A global homography cannot explain parallax, motion, or lens distortion across an arbitrary handheld scene.
  • Axis-aligned, single-scale patches can fail under large rotation, scale changes, low texture, or repeated structures.
  • Feathering averages disagreements; it does not remove geometric double edges or exposure differences.
  • Consensus residuals and four-corner fitting residuals are not independent accuracy measurements.
  • The rectified books use approximate display proportions rather than measured physical dimensions.
